Privacy policy

This describes the privacy design of RankBuddy. It will be finalised before the first public release.

What RankBuddy stores

RankBuddy stores the HackerRank personal access token you enter in the macOS Keychain and app preferences locally on your Mac. The token is sent only to HackerRank when it is needed for an API request; RankBuddy does not transmit your local preferences.

To display lists quickly after a relaunch, RankBuddy also caches the first API page for each account and section as JSON in its sandboxed Library/Caches/ListPageCache directory. The cache can contain the fields returned for tests, candidates, questions, interviews, people, and teams—including candidate names, email addresses, scores, assessment status, and related recruiting metadata. It also stores pagination cursors and result counts, but not the HackerRank access token.

Each cached page is replaced after a newer first page loads. RankBuddy does not currently apply a time-based expiry. macOS may purge files in the Caches directory, and RankBuddy clears an account's list-page cache when that account's token or server changes. Removing an account from RankBuddy does not currently remove its list-page cache; deleting RankBuddy's sandbox container as described below removes it.

Who RankBuddy talks to

RankBuddy contacts the HackerRank for Work API to fetch the data you ask it to display. There are no analytics services, advertising SDKs, or third-party telemetry endpoints.

A direct-download build may also use Sparkle to check for software updates. When that build includes an SUFeedURL, a manual update check—or automatic checks after you allow them—contacts the HTTPS host named in that URL to download its appcast. The host can receive the usual network metadata, including your IP address and HTTP request headers identifying RankBuddy and its version. RankBuddy does not enable Sparkle's optional system-profile reporting.

The current prerelease build has no update-feed URL configured and therefore does not contact an appcast host. The host will be identified here when the release feed is configured.

What RankBuddy does not do

  • It does not collect usage analytics or crash data on a third-party server.
  • It does not sell or share your data.
  • It does not require an account with the developer.

Your data, your control

Removing an account in RankBuddy removes that account and token from RankBuddy's current Keychain account list. Moving the RankBuddy app to the Trash does not automatically erase its other data.

After the app is removed, the following may remain:

  • preferences, cached API responses, and the local MCP activity log in RankBuddy's sandbox container;
  • RankBuddy account or recovery items in the macOS Keychain;
  • favourites synchronized through iCloud key-value storage; and
  • RankBuddy MCP entries that you installed in another application's configuration.

For a complete removal:

  1. While RankBuddy is still installed, remove its accounts in Account Settings and remove all favourites so those changes can synchronize to iCloud.
  2. Quit RankBuddy and remove the app.
  3. Delete only RankBuddy's container at ~/Library/Containers/com.adamdangoor.rankbuddy. If present, also delete ~/Library/Preferences/com.adamdangoor.rankbuddy.plist.
  4. Open Keychain Access, search for com.adamdangoor.rankbuddy, inspect the results, and delete the RankBuddy items.
  5. Remove the RankBuddy MCP server entry from each MCP client where you installed it.

Deleting these locations is permanent. Check each path and Keychain item carefully before removal; do not delete the surrounding Library, Containers, Preferences, or Keychain contents.
